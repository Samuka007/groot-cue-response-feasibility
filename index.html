Visible-Condition Response in GR00T-LIBERO: Level-0 Result and Latency Reference

Abstract

We first verified the standard GR00T-LIBERO system. Then we made the question deliberately small: a stationary cube is blue or red, the EEF stays fixed, and the policy only switches the gripper from open to close. Fresh SFT produced 12/12 red→close responses with 0/12 matched no-cue violations; the measured policy response on this setup is about 142–151 ms.

LEVEL 0 · The minimal task

A visible red condition switches one action.

The cube is static, the EEF is fixed, and the policy sees either blue/no-cue (stay open) or red (close). This asks one bounded question: can a visible condition map to an action without an always-close shortcut?

§4 · Policy latency reference

The measured policy response is about 142–151 ms.

These are two valid, independent evaluation artifacts. Together they give the current static cue-response setup a useful policy wall-clock reference—not a complete sensor-to-actuator latency or a theoretical model limit.

Why the artifacts are not in conflict

Short and extended are separate valid batches, so their small difference is not a contradiction and cannot be attributed to the post-response tail alone. The simulated result is 0 control steps: the action was selected on the first control tick with red visible. The wall-clock values measure this server-client policy request interval, not instantaneous physical response.

§5 · Scope

This proves condition → action, not a complete reflex.

The current result is deliberately narrow: in one fixed scene, an observed red condition drives one gripper action. Everything beyond that boundary remains unmeasured, not failed.

What is proved here

  • A visible visual condition can drive one action dimension.
  • The fixed-scene red→close mapping is learned after SFT.
  • Matched blue/no-cue episodes remain open.
  • The current setup supplies a 142–151 ms policy wall-clock reference.

What is not measured here

  • Temporal blue→red change detection or reaction to a changing world.
  • Moving-target following or cross-scene generalization.
  • Contact, grasping, lifting, holding, or recovery.
  • Full sensor→actuator latency or latency-induced failure curves.
§6 · Next stage

Grasp-ready static cube

Keep the cue-response logic, place the static cube inside the gripper’s closing envelope, and keep the EEF fixed. Treat contact as a secondary metric; do not add movement or lifting yet.

The key test: does the learned red→close response produce contact while the matched no-cue control stays open?
